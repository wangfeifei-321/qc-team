# QC-Team · 学术作业质检团队（命令行版）

一个可复用的质检工作流：给它一份学生作业稿件，三个不同的 AI（Claude / Codex / MiniMax）交叉核验，
再加一道**真实 API 文献核验**（不靠 AI 幻觉），最后出一份完整质检报告。

> 团队里任何人 clone 下来，都能跑出**同样水准**的质检 —— 解决"同一份 SOP 不同人给出不同结果"的问题。

---

## 它为什么和"直接问 AI 帮我质检"不一样

| | 直接问一个 AI | QC-Team |
|---|---|---|
| 文献真不真 | AI 可能幻觉出假文献 | **走 Crossref 真实 API 核验 DOI** |
| 会不会漏 | 一个模型的盲区 | **三个不同模型交叉挑错** |
| 查不到怎么办 | AI 可能编一个 | **如实标"查不到、待人工核验"，绝不编造** |
| 结果稳不稳 | 每次不一样 | **角色固化成文件，谁跑都一样** |
| 能不能复用 | 靠记忆/靠人 | **clone 即用，换任何稿件都能跑** |

---

## 核心设计：能确定性核验的交给程序，需要判断的交给 AI

- **文献是否真实存在** → 程序走 Crossref API 查证（`scripts/verify_refs.py`）。这一步**绝不让 AI 判断**，因为 AI 会幻觉。
- **文内引用和原文是否匹配、有没有漂移、推荐什么替代** → 三个 AI 角色交叉判断。

这是整个工具的灵魂：**把"能查证的"和"需判断的"分开。**

---

## 三个角色

1. **主审（Claude Code）** — `roles/01_主审_claude.md`
   核查文内引用 ↔ 原文是否匹配（最重要）、近似逐字串、无出处论断。
2. **复核（Codex）** — `roles/02_复核_codex.md`
   独立重做一遍，专挑主审的漏判/误判/过度自信。不盲目跟风，分歧如实保留。
3. **整理（MiniMax）** — `roles/03_整理_minimax.md`
   综合两方、判断文献权威性、推荐权威替代、整理可用观点、出完整报告。

> 三个不同厂商的模型 = 真正的交叉核验（不是同一个模型跑三遍，那样盲区还在）。

## 快速开始

### 1. 准备（每人一次）
- 电脑装好 **Codex**（命令行版，团队每人都有）
- 拿到团队共用的 **MiniMax** 和 **Kimi** 账号

### 2. 把稿件转成纯文本
把 `.docx` 另存/导出为 `.txt`（或用脚本转，见下）放进项目目录。

### 3. 跑
```bash
./qc.sh 你的稿件.txt
```
它会先做文献真实核验，然后打印出**第1/2/3步分别要喂给哪个 AI 什么文件**，你照着复制粘贴即可。

### 4. 拿报告
最终报告在 `reports/` 里。

---

## 报告包含哪些板块（对齐团队交付标准）

一句话结论 · 质检项目 · 文献核查（真实性/文内匹配/漂移/弱点/相似度/无出处）· 建议替换文献 ·
可用观点整理 · 提交前放行清单 · 风险与依据 · 核验凭据 + 保留的分歧

---

## 红线（写死在每个角色里）

- **查不到全文来源 → 如实说查不到，绝不编造文献存在**
- **推荐的替代文献不确定真实 → 只给方向，不编假 DOI**
- **分歧不强行统一 → 保留各方立场**

## 目录结构
```
qc-team/
├── qc.sh                    # 主命令：一条命令跑通
├── roles/                   # 三个角色定义（固化，不用每次重讲）
│   ├── 01_主审_claude.md
│   ├── 02_复核_codex.md
│   └── 03_整理_minimax.md
├── scripts/
│   └── verify_refs.py       # 文献真实核验（Crossref API）
├── samples/                 # 样例稿件
└── reports/                 # 质检报告输出
```

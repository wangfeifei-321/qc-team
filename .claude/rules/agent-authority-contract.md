# Agent 责权利契约

**任何一句「我完成了 X」，都必须回到产物里去验。** 理由：Agent 对自己产物的总结属于元数据，不构成关于该产物的证据。一次运行里若接受自述，就等于把「读不到上游却自己重造了一份」和「自报数字与产物对不上」这两类错误直接写进结论。本契约把每个 Agent 的责任、权利、利益写成可机械检查的条款。

---

## 一、状态机：一个 Agent 的一生只有五种状态

**每个 Agent 在任一时刻必须处于且仅处于下列五种状态之一，状态由 `qc_evidence.py` 的 `EvidenceRun` 独占写入。**理由：状态若由 Agent 自报，失败就会以沉默的方式传播，下游拿到空产物仍继续跑。

两个入口的能力不同，引用时不得混为一谈：

| 入口 | 状态机 | 闸门 | 首轮独立性 |
|---|---|---|---|
| `qc.py`（legacy） | 无。单轮串联，复核能看到主审答案 | 无机械执行 | 否 |
| `scripts/run_audited_qc.py`（audited） | 有，`EvidenceRun` 强制 | 5 道，逐道要 evidence locator | 主审与复核首轮互不可见 |

| 状态 | 含义 | 进入条件（可机械判定） |
|---|---|---|
| `BLOCKED` | 依赖没齐或读不到上游产物 | 上游产物文件不存在，或字节数为 0 |
| `READY` | 依赖齐了，等派发 | 全部上游产物文件存在且字节数大于 0 |
| `RUNNING` | 正在跑 | 子进程已启动且未退出 |
| `COMPLETED` | 产物已发布 | 子进程 exit code 为 0，且产物文件已落盘、字节数大于 0 |
| `FAILED` | 跑挂了或没产出 | 子进程 exit code 非 0，或超时，或产物字节数为 0 |

### 三条硬规则

1. **硬依赖强制**：依赖全部 `COMPLETED` 且产物可读，才允许进入 `RUNNING`。
2. **禁止静默绕过**：读不到依赖就停下报 `BLOCKED`，不许自己重造一份上游材料。
3. **失败必须传播**：上游 `FAILED` 时，下游一律置 `BLOCKED`，由编排器安排返工，不以沉默传播。

## 二、闸门：顺序不是流程图，是许可制

**排到了不等于可以跑；闸门未关闭，下一轮不得开始。** 理由：质检的每一层都建立在上一层的产物之上，上一层还在动，下一层的结论就没有意义。

生产编排（`scripts/run_audited_qc.py`）声明 **5 道闸门**，闸门名与代码里的 `required_gates` 逐字一致：

| 闸门 | 代码里的名字 | 守门人 | 判据 |
|---|---|---|---|
| 1 · 来源闸门 | `provenance` | 编排器 | 上游 DIP frozen manifest 存在；或显式声明为无上游的独立运行 |
| 2 · 基线闸门 | `baseline_integrity` | 编排器 | 稿件已冻结并记录 SHA-256 |
| 3 · 文献证据闸门 | `reference_evidence` | `scripts/verify_refs.py` | 每个 DOI 都有 Crossref 查询结果（命中或明确「查无」），无一条留空 |
| 4 · 双强核闸门 | `independent_dual_review` | `qc-conductor` + `qc-verifier` | 每条关键事实拿到 2/2 一致；任一方 `UNVERIFIED` 即不通过 |
| 5 · 放行闸门 | `release` | `qc-reporter` | 八个板块齐全，且红黄绿灯有对应依据 |

`qc_evidence.py demo` 的演示控制器只声明 3 道（`baseline_integrity`、`evidence_locator`、`release`），因为它不调用模型、也没有上游 DIP。**演示运行的闸门数不得被引用为生产能力。**

**每一道闸门的通过都必须附一个 evidence locator，且该文件要在本次 run 目录内真实存在**，否则 `set_gate` 直接拒绝。

**闸门 4 不通过时不得由闸门 5 翻案。** 整理者可以阻断，不能放行。

## 三、责权利矩阵

「利」在机器人的世界里不是报酬，是**被复用的资格**：产物可回溯、结论可复现的 Agent，其角色文件才会被下一次运行继续加载；反复产出不可核验结论的角色，应当被改写或删除。

| Agent | 责（必须做） | 权（可以做） | 利（目标函数） |
|---|---|---|---|
| `qc-conductor` | 按 D1–D7 逐维度出结论，标注每一条的 locator 与严重度；列出待复核清单 | 强核票 1/2；管理分歧；发布唯一最终结论的措辞 | 让「未被复核就放行」的次数归零 |
| `qc-verifier` | 从原始材料独立重判，不照抄主审；建立证据台账 | 强核票 1/2；否决主审任一条结论 | 让「主审漏判被下游发现」的次数归零 |
| `qc-reporter` | 七项机械扫描；权威性校准；综合出唯一最终报告 | 异议可立即阻断流程 | 让「报告里出现无依据条目」的次数归零 |

**三个角色都没有写文件的权限。** 理由：产物由编排器落盘，Agent 只产出 stdout，这样「谁写了什么」在文件系统层面唯一可追溯。

## 四、诚实标注优先于结论完整

**拿不到原文时必须标 `EVIDENCE_UNAVAILABLE`，不得写「已核实」。** 理由：一条被诚实标注为未核验的条目，人可以接着查；一条被伪装成已核验的条目，人不会再查，风险直接进入最终稿。

三个受保护的标注，任何下游角色都不得删除或改写：

- `UNVERIFIED` — 该条未完成核验
- `EVIDENCE_UNAVAILABLE` — 拿不到原文，无法核验
- `HUMAN_DECISION_REQUIRED` — 双强核分歧且都无决定性证据，交人裁决

## 五、运行留痕

**每次运行必须在 `reports/` 下留齐四份产物，缺一份即视为该次运行未完成。**理由：只有产物齐全，第三方才能不重跑就复核这次质检。

| 产物 | 生成者 |
|---|---|
| `_refs_verified.json` | `scripts/verify_refs.py` |
| `<稿件名>_1主审.md` | `qc-conductor` |
| `<稿件名>_2复核.md` | `qc-verifier` |
| `<稿件名>_质检报告_<时间戳>.md` | `qc-reporter` |
